项目概述
OpenOrigin 是一个开源软件供应链安全平台，核心功能包括 SBOM（软件 Bill of Materials）生成、依赖漏洞扫描（集成 Grype 引擎）、组件风险分析与可视化展示。系统对接 Git 仓库、解析依赖清单、调用漏洞数据库并生成安全报告。
信任边界
不可信输入：用户上传的 SBOM 文件（CycloneDX/SPDX 格式）、Git 仓库地址、包管理器锁文件（package-lock.json/pom.xml/go.mod 等）、前端表单提交的项目信息。
可信边界：内部漏洞数据库查询、Grype 扫描引擎调用、服务端内部任务队列。
重点审计组件
SBOM 解析模块：解析用户上传的 SBOM 文件和锁文件，重点关注 XML/JSON 解析漏洞（XXE、原型链污染）、路径穿越（通过恶意文件名写入服务器）。
Git 仓库对接：用户输入 Git URL 后服务端克隆仓库，重点关注 SSRF（输入内网地址）、命令注入（URL 拼接 shell 命令）。
Grype 引擎调用：服务端调用 Grype 扫描，重点关注命令行参数注入、临时文件竞争。
认证与授权：用户登录、项目权限隔离，重点关注水平越权查看他人 SBOM 报告、API Token 泄露。
文件上传：SBOM 文件上传接口，重点关注文件类型绕过、Zip Slip、恶意大文件 DoS。
前端可视化：ECharts 数据渲染，重点关注 XSS（组件名称、CVE 描述等用户可控字段未转义）。
严重性评级标准
严重 (Critical)：通过恶意 SBOM 文件或 Git URL 实现远程代码执行、SSRF 访问云元数据、未授权访问数据库。
高危 (High)：命令注入（Git 克隆参数）、任意文件读取 / 写入、认证绕过、水平越权查看他人项目报告。
中危 (Medium)：反射型 / 存储型 XSS、CSRF 敏感操作、SSRF 仅能访问本地端口、信息泄露（堆栈、内部路径）。
低危 (Low)：安全响应头缺失、日志泄露非敏感信息、版本号枚举。
不在审计范围
Grype 引擎本身的漏洞（由 Anchore 官方维护）。
第三方漏洞数据库（如 NVD、OSV）返回的数据内容。
测试代码 tests/、__tests__/ 目录。
前端静态资源中的第三方 CDN 依赖。
